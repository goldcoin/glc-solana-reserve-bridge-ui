# Migration Assessment — Old Bridge UI → New Reserve Bridge UI

Source audited: `/home/reaper/glc-solana-bridge-ui` (old wrapped-token/federation bridge frontend, read-only reference).
Target backend audited: `/home/reaper/work/glc-solana-reserve-bridge` (new reserve-backed bridge, read-only reference).

This document records the classification decisions that drove the rewrite. See git history of this
repository for the actual migration; this file is the rationale snapshot from the initial audit.

## Backend ground truth (summary)

- Off-chain HTTP API: hand-rolled `hyper` service in `service/src/api.rs`. No auth, no CORS, no TLS,
  no OpenAPI spec — hand-written TS types are the only option.
- Endpoints: `GET /status`, `GET /limits`, `GET /reserve`, `GET /health`, `GET /stats`,
  `GET /reserves/history`, `GET /explorer/events`, `GET /transfers`, `POST /transfers` (GlcToSol only),
  `POST /quote`, `GET /transfers/:id`.
- Fee is a fixed, compile-time bps rate (100 bps / 1% when this assessment was written; 300 bps /
  3% as of 2026-08-29 — always read the live rate from `GET /limits`), computed server-side only
  (`amount_conversion::compute_fee`). The client can never submit or override fee/net —
  `POST /transfers` silently ignores any such field.
- `RequestState` (real wire enum, `ledger/types.rs`): `LiquidityReserved`, `AwaitingDeposit`,
  `DepositObserved`, `Confirming`, `SourceFinalized`, `SettlementAuthorized`, `DestinationSubmitted`,
  `DestinationConfirmed`, `Settled`, `Expired`, `Cancelled`, `Reorged`,
  `InsufficientReserveAtSettlement`, `DestinationSubmissionFailed`, `ManualReview`, `Failed`. States
  after `SourceFinalized` are defined on the wire but not yet driven by an implemented code path — the
  UI must render every state without crashing but must not assume the full pipeline is exercised.
- `SolToGlc` has **no create endpoint**. The user must submit the on-chain `deposit_to_reserve`
  Anchor instruction directly (program id `BnCFcMaZtpXUzZhXZdQSeQWH4A2BMv5ZaebGe6Ysv2oY` — a
  **dev/localnet-only** id, not a production deployment), then discover the resulting transfer via
  `GET /transfers?address=...`.
- `GlcToSol` deposits require an `OP_RETURN` output (`6a20` + 32-byte `deposit_binding_hex`) on the
  Goldcoin deposit transaction, binding it to the `request_id`.
- Reserve capacity is exposed only as a derived `available_capacity` figure (never raw balances/signer
  data). Pause is tracked per direction, off-chain, in the ledger.
- No wrapped supply, no mint, no burn, no federation anywhere in the backend.

## Terminology removed from primary flow

`wGLC`, `wrapped`, `mint` (as an asset-creation concept), `burn`, `federation`, `token issuance` — all
absent from the new codebase's primary flow. `mint` still appears only in the narrow, accurate sense
of "the (existing, not newly-created) Token-2022 mint address" where unavoidable.
